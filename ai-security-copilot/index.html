AI Security Investigation Copilot

A decision-support tool that helps security analysts investigate suspicious activity: it groups related events into incidents, weighs competing explanations, works out what evidence is missing, and updates its assessment as new evidence arrives.

PythonSQLitePydanticpytestClaude API (next) · Code on GitHub

The problem

A typical monitoring tool sees 35 failed logins, then a success from a new IP, and raises an alert. An analyst then has to answer the real questions by hand: are these events related? Is it an attacker, an employee on a trip, or a misconfigured service? What would tell those apart? The Copilot is built to do that investigative work and show its reasoning, not just flag events.

How it works

  1. Ingest JSON / JSON Lines security logs. Bad records are quarantined with the reason instead of being dropped.
  2. Normalize every source into one event format, with timestamps converted to UTC and the raw record kept.
  3. Detect suspicious patterns with rules: brute force, failure then success, unfamiliar login, MFA disabled, privileges granted.
  4. Correlate detections into incidents when they share a user or IP within an hour, and record why they were grouped.
  5. Investigate: track evidence, competing hypotheses and versioned assessments for each incident.
  6. Next: an AI-assisted loop of assess → find gaps → plan queries → retrieve evidence → reassess, ending in prioritized recommendations for a human analyst.

What it does today

On the sample authentication logs, the pipeline turns 12 raw events into two incidents:

$ copilot ingest data/scenarios/legacy_sample/events.json --source authentication
12 stored, 0 duplicates, 0 quarantined
$ copilot analyze
Detections: 6 total, 6 new, 0 replaced
Incidents: 2 created, 0 updated, 0 merged, 0 unchanged
$ copilot incidents
INC-0001  high      5 detections  7 events  users: alice
INC-0002  low       1 detections  1 events  users: carol
$ copilot incidents INC-0001
Severity estimate: high
Grouped because: same source IP: 10.2.4.15; same source IP: 185.44.10.21; same user: alice

Detections (observations, not conclusions):
  [medium] brute_force_user: 3 failed logins for alice in 40 seconds
  [medium] failed_then_success: Successful login for alice 140 seconds after 3 failed attempts
  [high] mfa_disabled: MFA disabled for alice 120 seconds after login
  [high] privilege_granted: Privileges granted for alice 240 seconds after login
  [low] unfamiliar_login: Successful login for alice from previously unseen IP 185.44.10.21

The 5 detections against alice are linked into one incident with the reason recorded, while a normal user's activity produces no incident. Each detection is labeled an observation: the system doesn't claim the account is compromised. That judgment belongs to the investigation phases.

Design principles

  • Python controls the workflow. The model proposes; code validates every response before it can change an investigation.
  • Every conclusion cites evidence, and each piece of evidence states its limitations.
  • Hypotheses aren't facts. Support levels change only when matching evidence is cited, and every change is logged.
  • Investigations are bounded by iteration and time limits.
  • Humans stay in control. The Copilot recommends actions; it never disables accounts or isolates machines itself.

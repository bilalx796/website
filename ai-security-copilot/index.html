AI Security Investigation Copilot

A decision-support tool for security analysts: it groups related events into incidents, weighs competing explanations, works out what evidence is missing, and updates its assessment as new evidence arrives.

01 The problem

A typical monitoring tool

  • Sees 35 failed logins, then a success from a new IP
  • Raises an alert
  • Leaves the analyst to figure out the rest by hand

The Copilot

  • Links the events into one incident and says why
  • Weighs attacker vs. traveling employee vs. misconfigured service
  • Finds the evidence that would tell them apart, and shows its reasoning

02 How it works

📥Ingest

JSON / JSONL logs. Bad records are quarantined with a reason, not dropped.

🧹Normalize

One event format, UTC timestamps, raw record kept.

🚨Detect

Brute force, failure then success, unfamiliar login, MFA off, privilege grants.

🔗Correlate

Detections sharing a user or IP within an hour become one incident.

🗂️Track

Evidence, competing hypotheses and versioned assessments per incident.

🧠Investigate

Next: assess → find gaps → retrieve evidence → reassess, with AI.

03 What it does today

On the sample authentication logs, the pipeline turns 12 raw events into two incidents:

copilot: zsh
$ copilot ingest data/scenarios/legacy_sample/events.json --source authentication
12 stored, 0 duplicates, 0 quarantined
$ copilot analyze
Detections: 6 total, 6 new, 0 replaced
Incidents: 2 created, 0 updated, 0 merged, 0 unchanged
$ copilot incidents
INC-0001  high      5 detections  7 events  users: alice
INC-0002  low       1 detections  1 events  users: carol
$ copilot incidents INC-0001
Severity estimate: high
Grouped because: same source IP: 10.2.4.15; same source IP: 185.44.10.21; same user: alice

Detections (observations, not conclusions):
  [medium] brute_force_user: 3 failed logins for alice in 40 seconds
  [medium] failed_then_success: Successful login for alice 140 seconds after 3 failed attempts
  [high]   mfa_disabled: MFA disabled for alice 120 seconds after login
  [high]   privilege_granted: Privileges granted for alice 240 seconds after login
  [low]    unfamiliar_login: Successful login for alice from previously unseen IP 185.44.10.21

Alice's 5 detections are linked into one incident with the reason recorded, while a normal user's activity produces none. Each detection is labeled an observation: the system doesn't claim the account is compromised. That judgment belongs to the investigation phases.

05 Design principles

🐍Python controls the workflow

The model proposes; code validates every response before it can change an investigation.

🧾Every conclusion cites evidence

And each piece of evidence states its own limitations.

⚖️Hypotheses aren't facts

Support changes only when matching evidence is cited, and every change is logged.

⏱️Investigations are bounded

Iteration and time limits stop runaway investigations.

🧑‍💻Humans stay in control

It recommends actions; it never disables accounts or isolates machines itself.
